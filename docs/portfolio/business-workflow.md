# Business Workflow

**SIMULATED / Mock AI / Manual Confirmation**

| 状态 | 输入与界面 | 输出与人工门槛 |
|---|---|---|
| NEW → INTAKE | 新建客户，选模拟案例、填写代号 | 独立客户工作区；没有采购结论 |
| EXTRACTION | 客户、沟通、销售判断、未知、产品资料分栏 | I/S 和候选 E，保留原文 |
| HUMAN_REVIEW | 逐条核对类型、作者、命题方向 | 原文接受不等于语义确认；未审核命题不支持升级 |
| CUSTOMER_ANALYSIS | 已审核资料与可用关系 | 客户理解、已知与未知 |
| HYPOTHESIS | 有效支持、反证及未知 | 假设、强度、需验证问题 |
| VISIT_PREP | 假设及当前状态 | 人工确认拜访目标与计划 |
| ROLEPLAY | 销售发言、角色、人工行为标注 | 隔离模拟回复；结束后评分 |
| VISIT_RECORD | 独立模拟或真实脱敏记录 | 再次提取、再人工审核；不自动导入演练 |
| DEBRIEF | 本轮已确认新信息与此前状态 | 新增、变化、假设变化和下次重点 |
| OPPORTUNITY_CHECK | 当前有效 Evidence | 十维检查、Stage、为什么/缺什么 |
| ACTION_REVIEW | 模板动作草稿 | 接受/修改/删除，修改后需再接受 |
| VERSION_SAVE | 本轮审核与当前阶段有效 | 保存 V2/V3，下一轮继续 |

拜访记录后会回到 EXTRACTION → HUMAN_REVIEW，再进入 DEBRIEF。角色演练可由现有按钮跳过，但作品集完整演示至少完成一次。

## 版本时点

首次 `confirmBatch` 建立 V1，然后进入客户理解。因此 V1 快照并不保证已有假设、商机阶段和行动。首次拜访闭环并确认动作后保存 V2；再次拜访后保存 V3。文档或截图不能把当前草稿的分析伪装成已保存 V1 的内容。

## 销售意义

系统把“客户有痛点”“客户希望改善”“客户已开始采购”当成需要不同证据的命题。对于预算、权限、流程和采购节点，未知就是未知。客户友好、愿意聊天或销售演练得分高，都不能代替采购证据。
